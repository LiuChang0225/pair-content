# 会议纪要管线指引（录音 → 纠错 → 纪要）

面向 PAIR 用户的会议记录三段管线。三个环节各自独立可用，串起来效果最好：

```
① PAIR 会议记录（产品内置）      ② transcript-fixer（内容库）      ③ pair-meeting-minutes-skill（内容库）
   录音 + 百炼 ASR 转写    ──>      词典规则 + AI 全文纠错     ──>      多轮并行生成 + UNION 合并纪要
   %LOCALAPPDATA%\PAIR\            人名改动必须附权威引证              决策带原文引用、检索自测、
   pair\meetings\<id>.json         不确定项进评审队列                  Mermaid 图、中文输出
```

两个 skill 均来自 daymade/claude-code-skills（MIT，见 `THIRD_PARTY_NOTICES.md`），
transcript-fixer 为原样收录，pair-meeting-minutes-skill 为改造收录。

## ① PAIR 会议记录（录音与转写）

PAIR 桌面端内置会议记录功能（会议模式/麦克风模式），录音经百炼 ASR 实时转写。转写产物：

- 记录文件：`%LOCALAPPDATA%\PAIR\pair\meetings\<id>.json`，`sentences` 数组含毫秒级时间戳（`startMs`/`endMs`）与文本；`marks` 为会中打点；`notes` 为手记
- 音频块：同目录 `<id>/<序号>.pcm`（16kHz 原始音频，纠错存疑时可回听）
- **没有说话人分离**：转写句子不带发言人标签，说话人识别在第③步用文本推断+人工确认兜底

把转写稿交给 agent 的最简方式（PAIR 自带 Python）：

```
帮我把 %LOCALAPPDATA%\PAIR\pair\meetings\<id>.json 的 sentences 提取成带时间戳的 transcript.md
```

也可以直接在会议记录界面复制全文粘贴给 agent。

## ② transcript-fixer（转写纠错）

对 agent 说"**修复转写**"或"**fix this transcript**"即可触发。它做什么：

- **两阶段**：Stage 1 确定性词典规则（按项目域加载、风险分级、中文词边界防误报）→ AI 全文纠错（同音字、乱码术语、人名、中英混杂）
- **人名安全**：改名必须附权威引证（花名册/用户明确答复/音频证据），出现频率不作为身份证据；无把握就保留原文并进评审队列
- **评审队列**：不确定项持久化排队，可用自带 web dashboard 逐条裁决；有 pending 项时不会声明"最终版"
- **学习闭环**：确认过的修复收割回项目词典（`~/.transcript-fixer/contexts/<domain>.md`），越用越准

首次使用的依赖安装（一次性）：

```
python -m pip install -r <内容库目录>/skills/transcript-fixer/requirements.txt
```

依赖仅 httpx / filelock / jieba / rapidfuzz（纯纠错路径）。内网 pip 不通时向 PAIR 维护者反馈，
不要自行从外网拉包。**不需要**配置 GLM API key——那是无 agent 自动化路线，PAIR 场景用不到。

注意：上游文档里的脚本命令以 `uv run` 开头；工位上没有 uv 时直接用 `python scripts/<脚本名>` 等价执行
（依赖已按上装好即可）。

## ③ pair-meeting-minutes-skill（纪要整理）

对 agent 说"**整理会议纪要**"即可触发。要点：

- 3 个隔离上下文的 subagent 并行各生成一份完整纪要，UNION 合并防丢内容；合并阶段激进保留所有 Mermaid 图
- 每个决策必须带原文引用；行动项落到具体人不落"团队"；数字（范围/优先级/计数）逐字保留
- 检索自测：用没见过草稿的独立 subagent 反推"未来会被查的声明"，逐条命中测试后才交付
- 交付的是**草稿**：请逐行人工评审，通常要迭代几轮（术语冲突、命名撞车只有你知道）

## 边界与降级（Windows + 内网）

| 上游能力 | PAIR 现状 | 降级行为 |
|---|---|---|
| 跨 ASR 引擎音频验证（第二识别引擎裁片段复核） | 不可用：依赖未收录的 asr-transcribe-to-text，本地引擎 MLX 仅 macOS | skill 按自带证据升级政策降级：本地证据链（词典/花名册/上下文）+ 保留 pending，不强行猜 |
| 用 PAIR 会议记录重转写全量音频 | 可用，但百炼 ASR 与原始转写同引擎 | 只证明"覆盖了完整音频"，**不构成独立交叉佐证**，skill 要求明说这条边界 |
| 飞书妙记/腾讯会议源头标注说话人 | 若转写稿来自这些平台仍适用 | 纪要 skill 会先请你在源头平台标注后重新导出，文本推断只做兜底 |

## 隐私

会议录音与转写属内部敏感材料：两个 skill 的纠错与纪要生成全程本地（词典 + 本地 agent），
不需要外部 API；不要把原始录音/转写上传到任何外部服务。评审 dashboard 也只监听本机。
