# 开发流程指引（idea → ship）

面向非专业开发者的 PAIR 工程流程入门。全部流程 skill 为 Matt Pocock skills 原样收录（见 `THIRD_PARTY_NOTICES.md`），通过斜杠命令触发（agent 不会自动调用）。

## 一次性准备

在你的工作目录（代码仓库或空文件夹）里运行：

```
/setup-matt-pocock-skills
```

它会探查仓库并引导你选择 issue tracker（没有 GitHub/GitLab 远端时选**本地 markdown**，工单存放在 `.scratch/` 下，纯文件、零基础设施）、triage 标签和领域文档布局，然后写入 `docs/agents/*.md`。其余流程 skill 依赖这次配置；未配置时它们会提示你先运行本命令。

## 主流程

```
有想法 ──> /grill-with-docs ──> /to-spec ──> /to-tickets ──> /implement（逐张工单）
             盘问打磨+沉淀文档      凝练成 spec     拆成带依赖的工单      每张工单 TDD+评审+提交
```

- **不确定从哪开始**：运行 `/ask-matt`，按处境给你路由。
- **小改动**（一个会话能完成）：`/grill-with-docs` 打磨后直接 `/implement`，跳过 spec/工单。
- **多会话大工程**：走完整链路，每张工单开新会话 `/implement`，做完一张清一次上下文。
- **需要跑代码才能回答的设计问题**（状态模型/UI 长什么样）：`/handoff` 交接 → 新会话 `/prototype` → `/handoff` 带回结论。

## 各环节说明

| 命令 | 做什么 | 什么时候用 |
|---|---|---|
| `/grilling` | 无情盘问你的想法（底层原语） | 想单独压力测试一个决定 |
| `/grill-me` | 盘问，不留文档 | 没有工作目录时 |
| `/grill-with-docs` | 盘问 + 沉淀 GLOSSARY.md/ADR | 主流程入口，有工作目录时 |
| `/to-spec` | 把当前对话凝练成 spec 发到 tracker | 盘问结束、确认要建 |
| `/to-tickets` | spec 拆成垂直切片工单（含阻塞边） | spec 就绪后 |
| `/implement` | 实现一张工单：TDD → 测试 → 评审 → 提交 | 每张工单一个新会话 |
| `/tdd` | 单独的红绿循环纪律 | 不需要完整流程、只想 test-first 建一个行为 |
| `/code-review` | Standards + Spec 双轴评审 | 想评审分支/PR/工作区改动 |
| `/diagnosing-bugs` | 疑难 bug 诊断循环 | 报错/崩溃/变慢 |
| `/research` | 一手来源调研，产出 Markdown | 需要查文档/API 事实 |
| `/handoff` | 会话压缩交接文档 | 换会话、跨阶段传递上下文 |

## 进阶（对模型与运行时要求高，试点期请谨慎）

| 命令 | 说明 |
|---|---|
| `/implement-spec` | 并行 subagent + git worktree 编排整个工单任务图，汇入 integration branch |
| `/improve-codebase-architecture` | 扫描架构深化机会并出可视化 HTML 报告（报告样式依赖 Tailwind/Mermaid CDN，内网不可达时降级） |
| `/wayfinder` | 超出单会话的超大工作量：决策工单地图 |
| `/triage` | issue/外部 PR 分诊状态机 |

## 已知摩擦

- 部分 skill 文案提到 `/clear`、`/compact` 等 Claude Code 命令；在 PAIR/dsh 运行时对应"新开会话"与上下文压缩功能，语义一致、名称可能不同。
- 流程 skill 全部为英文原文（原样收录策略）；catalog 中的中文名称与描述用于 Hub 展示与检索。
